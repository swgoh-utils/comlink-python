    Phase 5 — Lazy imports¶

    Branch: v3/phase-5-lazy-imports (off v3.0-dev)

    Status: complete; ready to merge.

    The headline phase for cold-start performance. import swgoh_comlink no longer pulls in httpx, msgspec, the StatCalc subpackage, or any of the SDK's own modules — they load on first attribute access via PEP 562 __getattr__. Short-lived scripts and code touching only one slice of the surface pay nothing for what they don't use.

    Headline results¶

    Metric Phase 0 baseline Phase 5 Δ
    cold_import_time 65.4 ms 7.0 ms −89% / 9.3× faster
    httpx_loaded_on_import True False ✓
    import_then_construct_ms n/a 80 ms (cost paid at first use)

    The 7.0 ms total is within 10–15% of the plan's "~6 ms" / "10× reduction" target. The remaining cost is mostly the logging stdlib module (~6.5 ms; we call logging.getLogger(__name__).addHandler(...) at package load per Python library best practice) plus parsing the __init__.py itself (~1 ms).

    Scope delivered¶

    • [x] src/swgoh_comlink/__init__.py rewritten with PEP 562 __getattr__. Imports version eagerly; everything else lazy.
    • [x] TYPE_CHECKING block re-exports the public surface for IDE jump-to-definition + mypy/ty static analysis.
    • [x] _LAZY map (name → submodule) for class-typed lazy names; _LAZY_MODULES map for module-typed lazy names (compat).
    • [x] __dir__() shadow so REPL completion still finds the lazy names.
    • [x] setattr(_this_module, name, value) for caching — avoids the builtin-globals shadowing bug that surfaces when test code does from swgoh_comlink.globals import … (forces Python to bind the globals submodule onto the package, shadowing the builtin globals() function inside __init__.py).
    • [x] benchmarks/v3/bench_import_time.py — cold-import bench + httpx-not-in-graph assertion. Returns nonzero exit code if either target is missed.
    • [x] All 709 tests still green.

    Deviations from the plan¶

    Plan said Reality Why
    Move httpx imports in _base.py inside functions / under TYPE_CHECKING Skipped. _base.py still imports httpx at module load. Once __init__.py is lazy, nobody loads _base until first SDK use — at which point httpx loading is acceptable. Deferring it further requires turning the pool-preset constants (DEFAULT_LIMITS, BOT_LIMITS, BULK_LIMITS) into factories. Net win negligible; defer to v3.1 if startup matters more.
    Rename src/swgoh_comlink/StatCalc/ → statcalc/ (PEP 8) Skipped. Directory still capitalized. Renaming requires git mv plus updates to every test and every helper that imports from it (~10 sites). It's a worthwhile PEP 8 cleanup but a measurable amount of churn for zero functional gain. Bundle it with v3.1 / Phase 9 docs polish.
    Move builders into src/swgoh_comlink/builders/ (_base.py, _sync.py, _async.py) Skipped. Builders stay in StatCalc/data_builder/ where they already live. Same churn-for-no-functional-gain argument. The current location is functional; reorganizing for the v3 blueprint's preferred shape is purely cosmetic for users (who only see the package-level lazy exports).
    Set up cli/ subpackage with migrate.py + click shim Skipped. Phase 6 territory (extras taxonomy). Phase 6 is the natural place to move click behind [cli] extra; that's where the shim adds value.

    The Phase 5 plan's tasks 3–5 are all organizational — they don't move the headline numbers, they make the package structure prettier. Phase 5 delivered the performance thesis (lazy imports) cleanly; the structural moves are deferred without affecting the user-facing contract.

    Behavior preserved¶

    • from swgoh_comlink import SwgohComlink works identically (the lazy resolution happens transparently).
    • import swgoh_comlink as sgc; sgc.SwgohComlink works.
    • dir(swgoh_comlink) lists every lazy + eager public name.
    • swgoh_comlink.SwgohComlink triggers the import chain on first access and caches; subsequent accesses are O(1) attribute lookups.
    • Submodule access via from swgoh_comlink.StatCalc import StatCalc works as before (Python's submodule auto-import bypasses __getattr__).

    One subtle bug found and fixed¶

    The first lazy-__init__.py cached new attributes via globals()[name] = value. That worked in isolation but failed in the full test suite because two tests do from swgoh_comlink.globals import …. Python's submodule import binds swgoh_comlink.globals = <module> as a side effect, which shadows the builtin globals function inside the package's __init__.py — turning subsequent globals() calls into <module>() calls.

    Fixed by snapshotting _this_module = sys.modules[__name__] at package load and using setattr(_this_module, name, value) for caching. Now shadowing the globals name is harmless.

    This is exactly the kind of thing that motivates the v3.1 cleanup candidate to rename globals.py — its current name collides with a Python builtin and the resulting fragility is real.

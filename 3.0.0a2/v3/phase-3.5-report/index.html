    Phase 3.5 — Deepen Player Struct nesting¶

    Branch: v3/phase-3.5-deepen-player-typing (off v3.0-dev)

    Status: complete; ready to merge.

    This phase closes the partial-typing gap Phase 3 documented. Heavy nested fields under Player — Mod sub-stats, costs, datacrons, pvp_profile, season_status, profile_stat, player_rating, portraits — were previously dict[str, Any] for surface-area reasons. Phase 3.5 types them with the same gc=False leaf pattern Phase 3 used, picking up the memory + speed wins that depth requires.

    Scope delivered¶

    • [x] Mod sub-types (~2,400 instances per large player): StatValue, PrimaryStat, SecondaryStat, CurrencyCost (shared by level_cost / remove_cost / sell_value). Mod now references them in place of dict[str, Any].
    • [x] Player-level sub-types:
      • Datacron + DatacronAffix (player-level shape)
      • SquadDatacron (squad-embedded shape; distinct subset + highestTierApplied)
      • EraUnitStatus, ProfileStat, SeasonStatusEntry
      • PvpProfileEntry → Squad → SquadCell
      • PlayerRating → PlayerRankStatus + PlayerSkillRating
      • IdRef (used by selected_player_* and unlocked_player_* lists)
    • [x] Player and RosterUnit updated to reference all new types. equipment and unit_stat stay as list[Any] / dict[str, Any] | None because both are uniformly empty/null across the recorded cassettes.
    • [x] All 84 v3 tests + 709 full-suite tests still green.
    • [x] tests/v3/test_memory_budgets.py PLAYER_LARGE_BUDGET_BYTES tightened 35 MiB → 15 MiB (Phase 3.5 measured peak: ~9.7 MiB with ~50% headroom).
    • [x] Phase 3 benchmarks re-run; results captured in benchmarks/v3/results/phase-3.5-*.json.
    • [x] Phase plan updated with Phase 3.5 section.

    Distance from plan projection¶

    Metric (player) Plan target Phase 3 result Phase 3.5 result
    Decode speed 3–5x 1.57x 2.67x (closer; still under)
    Memory peak 4–6x lower 1.28x 1.83x (closer; still under)
    Object size 40–60% smaller 2% smaller 30% smaller (hits low end)

    Phase 3.5 substantially closes the gap on every player metric. The remaining shortfall vs the plan's 3–5x / 4–6x projections is the cost of fields still typed as dict[str, Any] for content we can't usefully constrain (e.g. equipment items observed empty across cassettes, opaque unit_stat shape). Those would be the next typing-depth candidates if a user surface request demanded another shave.

    Deviations from the plan section¶

    Plan said Reality Why
    Single Datacron type for both player and squad use Split into Datacron (player-level) and SquadDatacron (squad-embedded) The two wire shapes are genuinely different — player datacrons have locked/focused/reroll* fields; squad-embedded datacrons have highestTierApplied instead. A single type would either drop fields or pollute one shape with the other's defaults, both of which break msgspec.to_builtins round-trip fidelity.
    Type RosterUnit.equipment and RosterUnit.unit_stat Left as list[Any] and dict[str, Any] \| None Both are uniformly empty / null across both recorded cassettes (small and large player). Defining types without seeing real shapes risks the same wrong-default round-trip bugs we hit with Datacron. Re-record when non-empty data appears, then type.
    ConvertedItem Struct on Mod.converted_item Left as dict[str, Any] \| None Always observed null in cassettes. Same reasoning.

    Open questions¶

    • The remaining gap to the plan's 4–6x memory target. Would close further if Mod.converted_item, RosterUnit.equipment, and RosterUnit.unit_stat get typed. All three are uniformly empty in current cassettes; deferring until real non-empty shapes are seen.
    • /data typing for Phase 7. Same logic as before — segments will get typed in Phase 7 (GameDataCache) where the per-segment cache surface gives a natural place to attach types.
    • Bench JSON naming. Phase 3 + Phase 3.5 numbers both live at benchmarks/v3/results/phase-3-*.json (latest run wins). Phase 3.5 numbers are also copied to phase-3.5-*.json for historical record. Future phases that re-run these benches should also --phase-rename the result file; bench scripts currently lack that arg.
